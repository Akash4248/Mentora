# Mentora Connected Tool Calling Protocol

**Status:** STABLE (Milestone 2 Verified)  
**Package:** `mentora`  
**Endpoint:** `POST /ai/tutor`  
**Transport:** HTTP SSE (Server-Sent Events) with JSON Streaming  

---

## 1. Architectural Overview & Boundaries

In Mentora, the Flutter application harness (`MentoraAgentSession` backed by `flutter_agent_harness`) is the **sole owner of the agent run loop**. The remote backend gateway (`/ai/tutor`) serves strictly as an inference provider. 

To maintain offline/online parity:
1. The client registers capabilities in `CapabilityRegistry` wrapping `AgentTool`.
2. For each request, only an allowlisted subset of relevant tools is resolved to prevent context window bloat.
3. The client sends tool definitions in the request payload.
4. When the model invokes a capability, the backend streams a `tool_call` event.
5. The client executes the capability locally, executes any permission or safety checks, appends the result to `context.messages`, and submits a continuation turn.

---

## 2. Request Payload Format (`POST /ai/tutor`)

When tools are resolved for an active question, the client serializes them in the `tools` array field:

```json
{
  "question": "Calculate the speed of a car that travels 150 meters in 5 seconds.",
  "topic": "Motion",
  "grade": 9,
  "stream": true,
  "tools": [
    {
      "name": "calculate",
      "description": "Safely calculates an arithmetic or algebraic expression (e.g. 2 + 2 or sqrt(16)).",
      "parameters": {
        "type": "object",
        "properties": {
          "expression": {
            "type": "string",
            "description": "The mathematical expression to evaluate."
          }
        },
        "required": ["expression"],
        "additionalProperties": false
      }
    },
    {
      "name": "lookup_simulation",
      "description": "Looks up an approved interactive NCERT simulation for a science topic.",
      "parameters": {
        "type": "object",
        "properties": {
          "topic": {
            "type": "string",
            "description": "The chapter or topic name (e.g. Motion, Gravity, Pendulum)."
          }
        },
        "required": ["topic"],
        "additionalProperties": false
      }
    }
  ]
}
```

## 3. SSE Stream Events (`text/event-stream`)

The server streams lines starting with `data: <json>`.

### 3.1 Text Streaming Chunk
Standard progressive text generation chunk:
```http
data: {"chunk": "To find the speed, we divide distance by time."}
```

### 3.2 Tool Call Event
When the model decides to invoke a tool, it emits a `tool_call` object:
```http
data: {"tool_call": {"id": "call_1719918231000", "name": "calculate", "arguments": {"expression": "150 / 5"}}}
```

Fields:
- `id`: Unique tool call identifier generated by the model or gateway.
- `name`: Exact name matching one of the allowlisted tools provided in the request.
- `arguments`: JSON key-value pairs matching the tool's declared JSON schema.

Upon receiving `tool_call`, the client yields `TutorStreamToolCallEvent` and suspends stream consumption.

### 3.3 Completion & Heartbeat Events
```http
data: {"started": true}
data: {"heartbeat": true}
data: {"done": true}
data: [DONE]
```

---

## 4. Client Tool Execution & Authorization

Upon receiving a tool call:
1. **Permission Check:** `CapabilityRegistry.authorizeCall(toolName, arguments)` checks whether the tool is `CapabilityPermissionTier.readOnly` (auto-approved) or `stateChanging` (requires authorization).
2. **Execution:** If approved, `AgentTool.execute(arguments, cancelToken, onUpdate)` runs deterministically on the client.
3. **Cancellation:** If the turn is aborted by the user, the active `CancelToken` cancels execution promptly.

---

## 5. Continuation Turn Payload Format

Once the tool finishes, the harness records a `ToolResultMessage` in the session history and initiates a continuation turn to generate the final explanation.

The continuation turn prompt embeds the validated output:
```text
Calculate the speed of a car that travels 150 meters in 5 seconds.

[Tool Result (call_1719918231000)]: 150 / 5 = 30

Please answer the question incorporating the tool result above.
```

The gateway continues inference from this state, streaming the final answer incorporating the ground-truth calculated value:
```http
data: {"chunk": "Using the formula $v = d/t$, we have:\n$$v = \\frac{150\\text{ m}}{5\\text{ s}} = 30\\text{ m/s}$$\n\nThe speed of the car is **30 m/s**."}
data: {"done": true}
data: [DONE]
```

---

## 6. Offline Local Model Parity

When disconnected from the PiHub or internet, the local on-device engine (`llama-cli` / Bonsai / Gemma) uses the exact same tool definitions:

1. Tool schemas are serialized into the `<|im_start|>system` prompt block.
2. The local model outputs a fenced tool call block:
   ````text
   ```mentora-tool-call
   {"name": "calculate", "arguments": {"expression": "150 / 5"}}
   ```
   ````
3. `MentoraBackendClient._streamLocalLlmFallback` detects and strips this block, yielding a `TutorStreamToolCallEvent`.
4. The client harness handles the continuation turn identically, providing seamless behavior whether online or offline.

## 7. Error Handling Matrix

| Scenario | Behavior |
| :--- | :--- |
| **Unknown Tool Name** | Harness intercepts call, emits tool error `Unknown tool: "<name>"`, passes error into continuation turn for model recovery. |
| **Unauthorized Action** | Before-tool-call policy blocks execution, tool is not executed, returns `This action was not approved.` |
| **Tool Execution Exception** | Tool throws or returns descriptive error, captured as `ToolResultMessage(isError: true)` without crashing client. |
| **User Abort / Cancel** | `CancelToken` notifies tool and inference engine, generation halts immediately, state transitions to `aborted`. |
| **Context Limit Exceeded** | Agent loop halts when `maxModelTurns` (5) or `maxToolCalls` (4) is reached, protecting context budget. |
